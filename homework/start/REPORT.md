# Отчёт по задаче (Issue #7)

## Что реализовано
- **R1 (переименование и обрезка пробельных символов):** в `src/tasks.ts` добавлена функция `normalizeTitle`, которая удаляет по краям обычные пробелы, табуляцию (`\t`), неразрывный пробел (`\u00A0`), переносы строк и пробел нулевой ширины (`U+200B`). Пустое после очистки название при переименовании отклоняется, а в `src/App.tsx` выводится сообщение «Название не может быть пустым» (`role="alert"`).
- **R2 (скрытие унаследованных пустых записей):** функция `visibleTasks` скрывает задачи с пустым названием (`isBlankTitle`) во всех вкладках («Все», «Открытые», «Готовые»), не изменяя исходный массив `seedTasks`.
- **R3 (подсчёт открытых задач):** `openCount` считает только невыполненные задачи с непустым названием (на стартовых данных выводится `Открытых: 1`).

## Изменённые файлы
- `src/tasks.ts` — нормализация названий (`normalizeTitle`), проверка на пустоту (`isBlankTitle`), фильтрация видимых задач и подсчёт открытых.
- `src/App.tsx` — валидация ввода при переименовании и отображение предупреждения об ошибке.
- `src/tasks.test.ts` — модульные тесты для базовой логики, требований R1–R3 и пробела нулевой ширины `U+200B`.

## Результаты проверок
- `npm test`: проходят все 7 тестов в `src/tasks.test.ts`.
- `npm run build`: проверка типов (`tsc --noEmit`) и сборка (`vite build`) завершаются без ошибок.
- `evidence/app.png`: скриншот интерфейса в браузере (`Открытых: 1`, пустая запись с `id: 3` скрыта).
- `evidence/red.txt`: логи четырёх красных прогонов при намеренном внесении дефектов:
  - `(а)` отключение обрезки пробелов в `createTask`;
  - `(б)` отключение валидации в `renameTask`;
  - `(в)` отключение фильтрации пустых строк в `visibleTasks`;
  - `(г)` замена `normalizeTitle` на стандартный `.trim()` без учёта `U+200B`.
